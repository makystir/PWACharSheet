# Convergence review — Guided Disease Progression & Guided Corruption / Mutation

Two opt-in, off-by-default guided flows were added to the Notes tab: a per-active-disease **Guided Disease Progression** stepper and a **Guided Corruption / Mutation** stepper. Each is a portal overlay driven by a pure React-free reducer (`src/logic/guided-disease/`, `src/logic/guided-corruption/`), hosted by the existing panel that owns the reducer and the seeded `RollDialog` (`DiseasePanel`, `CorruptionCard`), mirroring the shipped `guided-cast` pattern. The flows suggest and arrange existing `diseases.ts` / `corruption.ts` values into a rulebook-cited order; they roll nothing, mutate nothing, and auto-advance nothing — every action routes through the shared `RollDialog` (characteristic/bare-skill tests) or the existing in-panel controls (mutation d100s, Gangrene Hit-Location).

Watch for: one bundled, out-of-task change — commit `19fe2ab`, a prototype-pollution guard on the endeavour/downtime class lookup — modifies existing pure logic and a pre-existing test, so the branch is not strictly additive at the commit level (confirmed). This was already ratified by the user as an accepted cross-task deviation in the prior pass.

**Verdict**: APPROVED

## High-level view

The two flows are strictly additive to the disease/corruption feature code: `DiseasePanel` and `CorruptionCard` keep their existing `handleSymptomTest` auto-roll, `handleGangreneLocation`, and in-card mutation roller byte-for-byte; the only new default-render DOM is one `GuidedCorruptionTrigger` on the card and one `GuidedDiseaseTrigger` per rendered active-disease row. `CorruptionCard` gains an optional `onRoll` prop (optional, so existing callers/tests stay green), threaded from `NotesTab`.

The seed-vs-guidance boundary is honoured exactly: seedable tests (symptom Endurance/Cool, Lingering Endurance, corruption-resistance Challenging+0 Endurance) route through the shared `RollDialog` via `resolveSeededTarget` — the one source of truth for base target and tooltip lines. Non-seedable d100s (mutation type/result, Gangrene Hit-Location) are never seeded; they close-and-return to the existing in-panel controls. The guide reads nothing back from any roll.

The reducers are fixed 3-step sequences, pure, total, clamped (no wrap), frozen-safe, with no auto-advance and `reset` deep-equalling the initial state — covered by fast-check property tests. One aria-modal at a time is enforced by rendering the guide only while `rollDialogState == null` (yield). Every calculated total displays through `BreakdownTotal` (Tooltip). All new mechanics carry Core citations verified against the rulebook: corruption trigger and Dissolution at Core p.183 (source line 8667), Pure Soul at Core p.142 (source line 6807 + index), disease timing/symptoms/Lingering at Core p.186–188; the Wounded "(+20)" printed inconsistency is deferred to `getSymptomTest` per A-3.

The one blemish is scope: a prototype-pollution hotfix to `endeavours.ts` / `downtime-recommendations.ts` (+ its test helper) rides along on the branch. It is behavior-preserving for valid data and rulebook-cited, and the user has already accepted it as a documented deviation rather than rewrite shared-branch history.

### No forked logic

The panels import and orchestrate the named `diseases.ts` / `corruption.ts` helpers (`getDiseaseSymptoms`, `getDiseaseProgress`, `getSymptomTest`, `symptomRollsHitLocation`, `getLingeringDifficulty`, `getToughnessBonus`; `getCorruptionThreshold`, `getPureSoulLevel`, `getMutationTypeDistribution`, `getPhysicalMutationLimit`, `getMentalMutationLimit`, `getCorruptionLossOnMutation`) and `resolveSeededTarget`. ### Seed-vs-guidance boundary

Seedable: symptom Endurance/Cool tests (`getSymptomTest` non-null, excluding Lingering which is Step 3 and Gangrene's location which is a hand-off), the Lingering Endurance test (Step 3), and the corruption-resistance Challenging (+0) Endurance test (Step 2) — each builds a `ReminderTest`, resolves it through `resolveSeededTarget`, and opens the shared `RollDialog` with a read-only base target and defaulted difficulty. Non-seedable: the corruption panel contains no `lookupMutation`/`determineMutationType`/roller-handler call and seeds no `RollDialog` for the mutation d100; Gangrene's Hit-Location button calls `handleClose` (close-and-return) and seeds nothing. Both hand-offs direct the player to the existing in-panel controls.

### Reducers + property tests

Both reducers switch on explicit event kinds with an exhaustiveness `default` returning `state`; `next`/`back` clamp with no wrap and return the same reference at a boundary; `goto` is a same-reference no-op when already on the step; `reset` returns a fresh initial constant; `start` (disease) binds `diseaseId` and resets to the first step. There is no event that advances a step except explicit `next`/`goto`/`start`, satisfying the no-auto-advance invariant. Property-test files are present for both (`reducer.property.test.ts`) asserting in-sequence membership, clamp/idempotence, reset-deep-equals-initial, determinism, and frozen-state safety, mirroring `guided-cast`.

### One aria-modal via yield

Each host renders its guide panel only when `rollDialogState == null`, so when the seeded `RollDialog` opens the guide un-mounts — exactly one `role="dialog" aria-modal` exists at a time, and the guide re-mounts at the same reducer step when the dialog closes.

### Tooltips on calculated totals

Every displayed total routes through the shared `BreakdownTotal` (wrapping `Tooltip` + `TooltipTriggerCell`): symptom/Lingering base target (from `resolveSeededTarget(...).lines`), Gangrene TB threshold, rolled Incubation/Duration (reusing `RolledTiming.breakdown`), corruption threshold, physical/mental mutation limits, and corruption-loss-on-mutation — each with additive labeled components and no hand-recomputed number.
